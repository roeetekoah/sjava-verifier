# Verification guide

Run `java tools/Project.java test` from the repository root with a full JDK 17 or newer. It rebuilds the verifier with `--release 17 -Xlint:all -Werror`, creates the local JAR, compiles the dependency-free test harness, and returns a nonzero process status if any check fails.

## Corpus

[`corpus/cases.tsv`](../corpus/cases.tsv) labels 93 original examples with expected stdout status, semantic rule IDs, expected diagnostic text fragments, and one-based error lines. Every `.sjava` corpus file must appear exactly once. Valid cases must have empty stderr; invalid cases must have the expected line and diagnostic. Every handled CLI case must exit normally, and stdout must contain exactly the result plus one newline. The suite invokes the built JAR, exercising packaging and the actual command-line path.

The corpus distinguishes accepted boundaries from forbidden features: same-line left-to-right initialization, numeric widening, global visibility after method definitions, shadowing, source-order initialization inside false branches, method isolation, nested returns, column-one comments, and unsupported expressions. Rule IDs refer to [the contract](../docs/language.md). The examples are specification-derived expectations, not labels generated by running the verifier.

## Additional cases

Ten input/error checks cover absent/extra arguments, missing files, wrong or uppercase suffixes, directories, malformed UTF-8, paths with spaces, CRLF, and an invalid path containing NUL (the last case calls `main` directly because a process launcher cannot pass NUL).

One hundred generated semantic cases cover all 25 type pairs in four contexts: variable initializers, assignments, method calls, and literal initializers. The oracle is an explicit expected conversion table in the test harness, independent of `TypeSystem`.

Eleven additional properties cover alpha-renaming, whitespace changes, method reordering, verifier reuse after failure, removing an initialization, per-method effect isolation, 300 nested scopes, and 60 independent methods. These cases exercise the verifier API without claiming execution or whole-language formal correctness.

## Limits

This is a bounded regression and behavioral suite. It does not prove conformance for every file, benchmark performance, exercise OS-specific permission denial, cover hostile resource exhaustion, or turn unsupported literal payloads/keyword names into supported syntax. The original supplied/community tests are intentionally excluded from distribution. Local historical checks are recorded separately in the release-readiness report.
